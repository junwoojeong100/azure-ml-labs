# Straightforwardness 평가

**결과: 95/100 — 아래 자체 문서 평가 기준의 S01–S19 충족, U20 미실시.**

이 점수는 **명시한 기준에 대한 자체 문서 평가**이지, 독립 평가자나 학습자 실험으로 측정한 객관적 사용성 점수가 아닙니다. 문서만 짧게 줄이는 대신 “무엇을 열고, 어디서 실행하고, 무엇을 보면 다음으로 가는가”를 확인합니다.

## 이번에 바꾼 점

이전 문서의 막힘 요소는 단순한 분량보다 다음과 같았습니다.

- 학습자가 kernel 준비를 찾으려고 200줄 이상의 강사용 인프라 문서에 들어가야 했습니다.
- “전체 프로젝트를 배치”하라는 설명에 최신 파일 취득·위치·설정 준비 방법이 빠져 있었습니다.
- Notebook은 7단계, CLI는 9개 번호여서 서로 대응하기 어려웠습니다.
- 실패 셀이 왜 정상인지, 기다리다 중단하면 어디부터 재개하는지, kernel 변경이 어떤 영향을 주는지 흩어져 있었습니다.

개선본은 **시작 안내 → Notebook 01–07 → 정리**를 기본 경로로 정했습니다. 제출/대기 셀을 분리하고 재개 ID, 명확한 준비 오류 메시지, 전환 응답 비교를 추가했습니다. 학습·평가·등록·배포의 구현과 품질 게이트를 완화하지 않았습니다.

## 검증 범위

2026-09-16 문서 개선 검증 결과:

- 로컬 문서/Notebook 링크와 section anchor가 모두 연결됩니다.
- README·Notebook·CLI의 01–07 제목과 세 가지 단계 안내 항목이 일치합니다.
- Bash 블록 문법과 Notebook의 모든 Python 셀 구문을 확인했습니다.
- Azure API를 대역으로 바꾼 Notebook 실행에서 **일반 진행과 kernel 재시작 후 재개**를 확인했습니다. 두 의도된 오류는 그대로 발생하고, 중복 Job/배포 없이 blue → green → blue 확인과 정리로 이어집니다.
- 기존 코드 검사와 문서 검사를 포함해 **41개 테스트가 통과**했습니다. 학습·평가·등록·배포 구현, 인프라, 기존 실행 증빙 JSON은 변경하지 않았습니다.

작업 중 `main`에 병합된 Dependabot의 MLflow 3.16.0·PyArrow 23.0.1 업데이트는 보존했습니다. MLflow와 skinny 버전이 충돌하던 lock 파일을 패키지 관리자로 다시 해결했고, MLflow 3에서 더 이상 기본 허용되지 않는 테스트용 파일 metadata store는 임시 SQLite로 바꿨습니다. 이는 합쳐진 브랜치에서 설치/검증을 가능하게 하는 최소 호환성 보완이며 Azure 실행 방식 변경이 아닙니다.

이번 작업에서는 Azure 리소스 생성·학습·추론·삭제를 다시 수행하지 않습니다. 기존 실제 실행 결과는 별도 기록으로 유지합니다. Studio 파일 공유의 이전 게시본은 자동 업데이트되지 않으므로 학습자 시작 안내는 최신 ZIP을 별도 폴더에 준비하도록 설명합니다.

문서 점수를 실제 학습자 경험으로 확인하려면 U20을 별도로 수행해야 합니다. 그 전에는 “실사용자 평가 95점” 또는 “완전한 무중단 실행을 새로 실증했다”고 표현하지 않습니다.
